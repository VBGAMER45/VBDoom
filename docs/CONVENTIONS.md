# DoomVB porting conventions

How the C code of linuxdoom-1.10 (in `ref/linuxdoom-1.10`) is translated to VB6.
Build with `python tools\build.py` (add `--release` to drop array bounds checks).
`python tools\check_names.py` finds case-insensitive name clashes in one pass.

## Structure

* One `.bas` module per C file, same name (`r_main.c` -> `src/r_main.bas`).
  Module names must not equal a procedure name (`m_random` clashed with
  `M_Random`, so that module is `m_random_c`).
* Shared types, constants and globals live in `src/doomdef.bas`. A global that
  is `extern` in a C header goes there; file-local C globals become `Private`.
* Clusters not yet ported are replaced by `stubs/stubs_*.bas` (generated by
  `tools/gen_stubs.py`). `tools/build.py` writes `DoomVB.vbp` from what is in `src/`.
* Data tables (info.c, sounds.c, d_englsh.h, d_items.c, tables.c) are generated
  by `tools/gen_tables.py` - never edit the generated files by hand.

## Pointers become indices

| C | VB |
|---|----|
| map data (`vertex_t*`, `sector_t*`, `line_t*`, `side_t*`, `seg_t*`, `subsector_t*`, `node_t*`) | 0-based index, NULL = -1 |
| `mobj_t*` and every thinker (ceilings, doors, ...) | thinker slot (1-based), NULL = 0 |
| `player_t*` | player number 0..3, NULL = -1 (`mobj.player`) |
| `state_t*` | state number (`S_NULL` = 0) |
| `patch_t*` | lump number |
| cached lump `byte*` | byte offset into `wadbuf()` (`W_CacheLumpNum`) |
| `lighttable_t*` | offset into `colormaps()` |
| function pointers | id constant + `Select Case` dispatcher (`AF_xxx`, `TF_xxx`, `ITER_xxx`, `TRAV_xxx`) |

All thinkers share one slot space: `thinkers(t)` holds the list links and
function id, and `mobjs(t)`, `ceilings(t)`, `doors(t)`, ... are the per-type
records for the same slot. Never `ReDim` those arrays except in the grow
routine, and never use `With mobjs(x)` (a With block locks the array).

## VB6 pitfalls (each one has bitten this port already)

* **Integer literals are 16-bit.** `10240 * 4` overflows (silently, with
  overflow checks off). Write `10240& * 4`. Hex `&H8000`..`&HFFFF` are negative
  Integers: use `&H8000&`, `&HFFFF&`.
* **Operator precedence:** comparisons bind tighter than `And`/`Or`:
  `If flags And MF_SOLID <> 0` is wrong - write `If (flags And MF_SOLID) <> 0`.
  `\` binds tighter than `And`: write `(x And &HFFFF0000) \ &H10000`.
* **No short-circuit:** `If a >= 0 And arr(a) = 1` evaluates `arr(-1)`. Nest Ifs.
* **`/` is floating point.** C integer `/` is `\` (truncates toward zero, like C).
* **Shifts:** `x >> 16` on a possibly negative value is `(x And &HFFFF0000) \ &H10000`
  (`x \ 65536` truncates instead of flooring). Helpers: `SAR`, `SHR` (logical),
  `SHL`, `FIXTOINT`, `FINEANGLE` (angle -> fine index).
* **Unsigned:** `angle_t` is unsigned in C. Compare with `ULT/UGT/ULE/UGE`.
  Adding/subtracting angles wraps correctly (overflow checks are off).
* **`Not` is bitwise:** for a Long used as a boolean write `x = 0`, not `Not x`.
* **Module-level declarations must come before the first procedure.**
* **Reserved-ish names** to avoid as identifiers: `scale`, `line`, `name` (as a
  variable), `width`/`height` as globals, `type`, `next`, `step`, `len`, `left`,
  `right`, `time`, `date`, `point`, `print`, `open`, `close`, `get`, `put`,
  `me` (the keyword `Me`; wi_stuff's `me` is `myplayer`).
  C field `type` is `typ` (`mtype` in mobj_t), `next` is `nxt`.
* **Case-insensitive names:** `VIEWHEIGHT` (const) clashes with `viewheight`
  (global), so the constant is `PLAYER_VIEWHEIGHT`. The same holds inside one
  module (`SP_SECRET` vs `sp_secret` in wi_stuff), which check_names.py does
  not see; only the compiler reports it.
* **Editing the sources by script:** the files are CRLF. Python's text mode
  turns them into `\n`, so never split on `\r\n` after a text-mode read, and
  compare the line count before writing a file back. The Edit tool is safer.
* **API error codes:** read `Err.LastDllError`, not `GetLastError` /
  `WSAGetLastError` - the VB runtime overwrites the thread's last error right
  after a Declare call returns (i_net got "error 0").
* Pass scalars `ByVal` (VB defaults to ByRef). UDTs and arrays must be ByRef.
* `IIf` evaluates both branches - use If blocks.
* Compiled code only: integer math relies on wrap-around (overflow checks off).

## Compiler settings: no optimization

`tools/build.py` compiles native code with **No Optimization**. With "Optimize
for Fast Code" the VB6 compiler miscompiled `EV_Teleport` (a register holding
the teleporting mobj was overwritten by the thinker loop variable, so an ammo
box teleported instead of an imp). The bug vanished whenever the procedure
was changed slightly, so it cannot be avoided by rewriting one function. The
unoptimized build still renders demo1 at roughly 950 fps (35 needed).

Integer overflow checks and floating point checks are removed (the code relies
on wrap-around). Array bounds checks stay on unless `--release` is passed.
`FixedDiv` is computed exactly (as the DOS assembly did) so results never
depend on how floating point intermediates are rounded.

## Debugging tools

* `python tools\debugbuild.py` builds `DoomVB_debug.exe`: every procedure gets
  line numbers and an error handler, so a run time error logs a call trace
  (`at module.procedure line N`) to `doomvb.log`.
* `-checklinks` verifies every sector / blockmap thing list each tic and traps
  removal of linked or dead mobjs.
* `-synclog file` writes one line per tic (random index, mobj count, position
  checksum). Diff two runs to find the first tic where they diverge.
* `-watch slot` logs spawn / state changes / removal of one thinker slot.
* `-timedemo demo1 -hidden -nosound -nomouse` plays a demo as fast as possible
  and logs the frame rate; `-shot <tic> <file.bmp>` saves screenshots.
* `-key <tic>[+<n>] <key>` scripts key presses (menus, movement) for hidden
  runs; pair it with `-config <scratch copy>` to keep `default.cfg` unchanged.
  `-hidden` ignores the real keyboard, so scripted runs are reproducible.
* `-exitat <tic>` exits the level at a gametic (intermission and finale tests).
* `-sndcapture <file.wav>` mixes the sound effects into a WAV file (one tic of
  audio per gametic) and `-muslog <file>` lists the streamed music events;
  neither opens a device, so hidden test runs stay silent.
* Net games on one PC: start each copy with its own `-port` and the others as
  `-net <n> .127.0.0.1:<port> ...`; run the second and third copy from their
  own folders (with `-iwad`) so the doomvb.log files do not collide, and diff
  their `-synclog` files. `-netdrop n` drops every n-th packet sent (tests
  resending); `-debugfile` logs every packet to debug<player>.txt.
